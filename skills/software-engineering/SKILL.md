# 软件工程建模技能

## 先问题，后图

每张图只回答一个主要问题：

| 问题 | 首选图 | 核心元素 |
| --- | --- | --- |
| 谁使用系统、系统提供什么 | 用例图 | Actor、Use Case、系统边界 |
| 对象之间怎样协作完成一次调用 | 时序图 | Participant、Message、Guard |
| 有哪些实体、状态如何流转 | 状态图 | State、Transition、Event |
| 业务步骤和分支是什么 | 活动图 | Activity、Decision、Fork/Join |
| 领域对象及静态关系是什么 | 类图 | Class、Attribute、Operation、Relationship |
| 数据实体及基数关系是什么 | ER 图 | Entity、Key、1:N |
| 系统由哪些可替换模块构成 | 组件图 | Component、Provided/Required Interface |
| 软件部署到哪些物理/虚拟节点 | 部署图 | Node、Artifact、Communication Path |
| 数据在外部实体、过程、存储之间怎样流动 | DFD | External Entity、Process、Data Store |

## 信息抽取

- 参与角色：谁发起、谁审批、谁接收结果。
- 对象：需求中的稳定名词，避免把每个动词都变成类。
- 行为：需求中的动词，映射到用例、方法、消息或活动。
- 规则：金额、权限、时限、状态前置条件，映射到 guard 或 notes。
- 数据：关键字段、主键、外键、基数。
- 非功能要求：安全、缓存、异步、可用性，通常在组件/部署图中体现。

题目没有给出的关键信息，不应假装确定。使用合理的最小假设，并写入 notes。

## 关系语义

- 继承：子类型到父类型，箭头指向父类型。
- 实现：具体类到接口，虚线空心三角。
- 组合：整体生命周期控制部分，从整体到部分，实心菱形。
- 聚合：整体包含部分但生命周期独立，从整体到部分，空心菱形。
- 依赖：临时使用、参数、创建或调用，虚线开放箭头。
- 关联：长期结构连接，可标注角色和多重性。

## 质量约束

- 一张图通常 5-18 个核心节点；更大的问题先分层。
- 关系应当有方向含义，图上不要出现无意义的双向箭头。
- 图题说明“是什么问题”，副标题说明“这张图回答什么”。
- 把正常路径和异常路径分开表达；时序图不要把每个内部函数都画进来。
